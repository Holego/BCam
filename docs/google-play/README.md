## 1. Как получить файл `.aab`

Подписанный `.aab` собирается командой `bundlePlayRelease`. Есть два способа; ключ в чат
присылать **не нужно** ни в одном из них.

### Способ A — в облаке, через GitHub Actions (ничего не устанавливается)

Один раз:

1. Слейте ветку в `main` (workflow с ручным запуском виден только на главной ветке).
2. На ПК закодируйте ключ в base64. PowerShell:
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\GoshanData\keys\bcam-release.jks")) | Set-Clipboard
   ```
3. GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
   Создайте четыре секрета:

   | Имя | Значение |
   |---|---|
   | `RELEASE_KEYSTORE_BASE64` | содержимое буфера из шага 2 |
   | `RELEASE_STORE_PASSWORD` | пароль хранилища (новый, см. раздел 2) |
   | `RELEASE_KEY_ALIAS` | `bcam` |
   | `RELEASE_KEY_PASSWORD` | пароль ключа. Для файла формата PKCS12 (по умолчанию у современного `keytool`) он **всегда совпадает с паролем хранилища** — впишите то же значение |

Перед сборкой workflow сам проверяет ключ и называет причину, если что-то не так, не показывая
пароли: неверный пароль хранилища, несуществующий alias, разные пароли у PKCS12, пробел или
перевод строки в конце секрета. Ошибка вида `keystore password was incorrect` означает, что
`RELEASE_STORE_PASSWORD` не равен тому паролю, который в данный момент у файла `.jks`.

Каждый раз, когда нужен файл: **Actions → «Release AAB for Google Play» → Run workflow**.
Через несколько минут внизу страницы запуска появится артефакт **`play-release-aab`** (zip с
`app-play-release.aab`). В логе будет показано, каким ключом подписан файл (отпечатки SHA-1/SHA-256).

### Способ B — у себя на ПК (одна команда)

У вас уже настроен `local.properties` с ключом, поэтому:

```
gradlew bundlePlayRelease
```

Результат: `app\build\outputs\bundle\playRelease\app-play-release.aab`. Нужны JDK 17 и Android SDK 36
(Android Studio предложит доустановить сам).

> Почему не собрал в этой сессии: в облачном окружении Claude заблокирован хост `dl.google.com`,
> откуда скачивается Android SDK. Поэтому проверочные сборки шли в GitHub Actions — там SDK есть.
> Результат этих сборок виден во вкладке **Actions** репозитория.

## 2. Ключ подписи: пароль утёк в публичный репозиторий

В коммите `dd34700` пароль от хранилища (он же пароль ключа) попал в `.gitignore` и лежал в
открытом репозитории. Сам файл `bcam-release.jks` в git **никогда не попадал** (проверено по
всей истории), так что ключом воспользоваться нельзя, пока файл не утёк. Но пароль нужно сменить:

```
keytool -storepasswd -keystore C:\GoshanData\keys\bcam-release.jks
```

Это **одна** команда. У файла формата PKCS12 (так создаёт `keytool` с JDK 9+) пароль ключа и
пароль хранилища — одно и то же значение, и отдельная команда `keytool -keypasswd` для него
не поддерживается (выдаёт ошибку). Тип файла видно по строке `Keystore type` в выводе
`keytool -list -keystore …`. Новый пароль впишите **в оба** места: `RELEASE_STORE_PASSWORD` и
`RELEASE_KEY_PASSWORD` (в секретах GitHub и в `local.properties`). Для старого формата JKS пароли
можно менять отдельно (`-storepasswd` и `-keypasswd -alias bcam`).

Из `.gitignore` пароли уже убраны;
в истории они остаются — переписывать историю публичного репозитория смысла нет, достаточно сменить
пароль.

**Что будет ключом для Google Play.** Используйте Play App Signing (включён по умолчанию): Google
хранит настоящий ключ подписи приложения, а ваш `bcam-release.jks` — только **ключ загрузки**
(upload key). Если его потерять или он утечёт, доступ восстанавливается через поддержку Play
Console — это не катастрофа, в отличие от потери обычного ключа подписи. Побочный эффект: APK из
Google Play подписан другим ключом, чем сборка F-Droid/GitHub, поэтому между источниками обновляться
«поверх» нельзя (нужно удалить и поставить заново). Это нормально.

## 3. Аккаунт разработчика

- Регистрация: <https://play.google.com/console/signup>, разовый взнос $25, проверка личности и
  платёжный профиль.
- **Личный аккаунт, созданный после 13 ноября 2023:** перед выходом в Production нужно провести
  **закрытое тестирование минимум с 12 тестировщиками в течение 14 дней подряд**. Если число
  участников упадёт ниже 12, отсчёт может сброситься. Точные условия для вашего аккаунта смотрите на
  дашборде Play Console («Тестирование вашего приложения»); правила периодически меняются.
  Аккаунты организаций (нужен D‑U‑N‑S) этому требованию не подлежат.
- Практический совет: создайте Google Группу, добавьте её как список тестировщиков и разошлите ссылку
  на участие друзьям; пусть реально запускают приложение.

Скриншот из `fastlane/.../phoneScreenshots/1.jpg` для Google Play **не подходит**: пропорции

соотношение 2,22 : 1 — обрежьте до 9 : 16 (например 1080×1920). Что снять: главный экран с
настройками; диалог выбора камеры/качества; идущую запись (уведомление с кнопкой «Стоп»);
рабочий стол с виджетом. Рекламу на скриншотах лучше не показывать.

### 5.3 Безопасность данных (Data safety)

Видео и звук записываются **только на устройстве** и никуда не передаются, поэтому по определению
Google (`collect` = передача с устройства) они **не декларируются**. Декларируется то, что собирает
рекламный SDK Google Mobile Ads (AdMob). Официальный перечень зависит от версии SDK — сверьтесь со
страницей [Google Play data disclosure](https://developers.google.com/admob/android/privacy/play-data-disclosure)
(в приложении SDK 25.4.0). Рекомендуемые ответы:

**Общие вопросы**

| Вопрос | Ответ |
|---|---|
| Собирает или передаёт ли приложение обязательные типы данных? | **Да** |
| Все ли данные шифруются при передаче? | **Да** |
| Есть ли способ запросить удаление данных? | **Нет** (аккаунтов нет, у разработчика данных нет; рекламный ID пользователь сбрасывает сам). Если консоль настаивает — укажите URL политики конфиденциальности |
| Следует ли приложение Families Policy | Нет |

**Типы данных** (для каждого: *собирается — да, передаётся третьим лицам (Google) — да, обрабатывается эфемерно — нет, обязательно — да*)

| Категория → тип | Цели |
|---|---|
| Местоположение → **Приблизительное местоположение** | Реклама или маркетинг; предотвращение мошенничества, безопасность, соответствие требованиям |
| Данные приложения → **Взаимодействие с приложением** | Реклама или маркетинг; аналитика; предотвращение мошенничества |
| Информация о приложении и производительность → **Журналы сбоев**, **Диагностика** | Аналитика; предотвращение мошенничества |
| Идентификаторы устройства или другие → **Идентификаторы устройства или другие** (рекламный ID) | Реклама или маркетинг; аналитика; предотвращение мошенничества |

Покупка делается через Google Play Billing: данные платежа приложение не получает, декларировать
«Финансовую информацию» не нужно. Лучше заявить лишнее, чем недозаявить: расхождение между формой и

использует рекламный ID. Цели: *Advertising or marketing*, *Fraud prevention, security and
compliance* (при желании — *Analytics*). В манифесте уже есть `com.google.android.gms.permission.AD_ID`.

### 5.4 Foreground-сервисы (обязательно, иначе релиз не пройдёт)

Приложение целится в Android 14+ и использует foreground-сервис типов `camera` и `microphone`.
Play Console → App content → **Foreground service permissions**: для каждого типа нужны описание,
последствия отложенного выполнения и **ссылка на видео** (YouTube, «по ссылке»).

**Camera**

- *Описание функции:* `Background Camera records a video that the user starts and stops from a home-screen widget or the ongoing notification. The camera foreground service type is used while the video is being recorded, including with the screen off. A persistent notification with a Stop button is shown for the whole recording.`
- *Что будет, если задача отложена или прервана:* `The recording would stop or never start and the user would lose the video. Capturing video is real-time and user-initiated, so it cannot be deferred or run without a foreground service: Android revokes camera access from apps that leave the foreground.`

**Microphone** (только когда пользователь включил «Запись звука»)

- *Описание функции:* `When the user enables "Record audio", the same recording also captures the microphone so that the video has sound. The microphone foreground service type is declared for that case only.`
- *Что будет при прерывании:* `Audio would be cut off or missing from the recording.`

**Видео-демонстрация (30–60 сек, одно на оба типа)** — показать по шагам:
1. Открыть приложение, выбрать папку, камеру, качество, включить звук (выдать разрешения).
2. Свернуть приложение, на рабочем столе нажать виджет **REC** — запись идёт, в шторке видно
   уведомление с кнопкой «Stop», в статус-баре — индикатор камеры/микрофона.
3. Выключить экран, подождать 10–15 секунд, включить.
4. Нажать «Stop» в уведомлении (или виджет ещё раз) — запись завершена, файл в выбранной папке.
5. Открыть файл и показать, что он воспроизводится.

### 5.5 Остальные разрешения

`CAMERA`, `RECORD_AUDIO`, `POST_NOTIFICATIONS`, `WAKE_LOCK` специальных деклараций не требуют.
`INTERNET`, `ACCESS_NETWORK_STATE`, `AD_ID` нужны рекламе и биллингу.

## 7. Подписка «Без рекламы»

Вместо разовой покупки приложение продаёт **подписку с автопродлением**. Цена и период продления
задаются только в Play Console: приложение читает их у Google Play и подставляет в кнопку
(например «Отключить рекламу — 9,00 $ в год»). Сменить месячную подписку на годовую можно без
обновления приложения.

> Вы не уточнили цену и период, поэтому в коде их нет. Прежние $9 как разовая цена ближе всего к
> подписке **за год**; $9 **в месяц** за отключение рекламы в утилите для большинства покажется
> дорого. Решайте сами — в приложении ничего менять не придётся.

Play Console → **Monetize with Play → Products → Subscriptions → Create subscription**:

| Поле | Значение |
|---|---|
| **Product ID** | **`ad_free`** — именно так, как в коде; изменить потом нельзя |
| Название | `Ad-free` (RU: `Без рекламы`) |
| Описание | `Turns all ads off while the subscription is active.` / `Отключает всю рекламу, пока подписка активна.` |

Затем в этой подписке **Add base plan** (создайте **ровно один** базовый план):

| Поле | Значение |
|---|---|
| Base plan ID | любой, например `yearly` |
| Тип | Auto-renewing (с автопродлением) |
| Период | на ваш выбор: неделя, месяц, 3 или 6 месяцев, год |
| Цена | ваша; цены для других стран Google пересчитает, правьте при желании |
| Grace period / Account hold | оставьте включёнными по умолчанию: при сбое платежа подписчик не теряет доступ сразу |
| Resubscribe | включите (можно оформить заново после отмены) |

Нажмите **Activate** у базового плана. Бесплатный пробный период можно добавить как **Offer**: приложение
автоматически выберет самое дешёвое доступное для пользователя предложение, а остальное покажет
сам лист оплаты Google Play.

Если вы уже успели создать разовый товар `remove_ads` — он больше не используется: не активируйте
его или удалите.

Важно:
- Подписка заработает, только когда в Play Console загружен хотя бы один релиз (любой трек) с этим
  `.aab`, а тестируемый аккаунт — в списке тестировщиков.
- **Settings → License testing**: добавьте свой Gmail — покупки тестировщиков бесплатны; тестовые
  подписки продлеваются ускоренно (месяц — за несколько минут) и сами заканчиваются, на них удобно
  проверять, что реклама возвращается после окончания.
- Пока подписка не создана или не активна, кнопка покажет просто «Отключить рекламу (подписка)»,
  а при нажатии сообщит, что покупки недоступны.
- Состояние подписки приложение спрашивает у Google Play при каждом запуске: переустановка, новый
  телефон, отмена (доступ идёт до конца оплаченного периода), окончание, возврат денег и приостановка
  из-за неоплаты учитываются сами.
- **Политика подписок Google Play:** условия должны быть видны *до* оформления. Приложение показывает
  цену, период, «продлевается автоматически, пока вы не отмените» и где отменить, а после оформления —
  ссылку «Управление подпиской». Не убирайте эти элементы и не обещайте в карточке «навсегда» или
  «разово».
- Проверки на сервере нет (бэкенда нет): для отключения рекламы это обычный компромисс.

Как реклама отключается: у подписчика рекламный SDK вообще не запускается. Дополнительно есть
бесплатный путь — «Посмотреть видео — без рекламы 24 часа» (rewarded) и предложение такого же видео
после остановки записи (rewarded interstitial).

## 8. AdMob

Идентификаторы блоков зашиты в [`AdUnits.kt`](../../app/src/play/java/io/github/holego/bcam/monetization/AdUnits.kt);
ID приложения — в `app/build.gradle.kts`.

| Формат | ID блока | Где показывается |
|---|---|---|
| Баннер | `ca-app-pub-6234952902147314/7765454659` | внизу главного экрана |
| Межстраничное | `…/1699748918` | после остановки записи кнопкой в приложении (через раз, не чаще чем раз в 3 мин) |
| Межстраничное с вознаграждением | `…/5602325743` | то же место, через раз; перед показом — диалог «Посмотреть видео? / Не сейчас» |
| С вознаграждением | `…/2106943022` | кнопка «Посмотреть видео — без рекламы 24 часа» |
| Нативное | `…/5906587234` | карточка с пометкой «Реклама» под настройками |
| Запуск приложения | `…/7894367035` | при возврате в приложение после ≥ 20 сек отсутствия (не при первом запуске) |
| **ID приложения** | `ca-app-pub-6234952902147314~5684803993` | манифест |

Принципы: реклама **никогда не показывается во время записи** и при работе через виджет/уведомление
(приложение при этом даже не открыто). При активной подписке или награде — не показывается вообще.

**Что нужно сделать в AdMob:**

1. **Privacy & messaging → GDPR** — создайте и опубликуйте сообщение о согласии (UMP) для ЕЭЗ,
   Великобритании и Швейцарии. Пока оно не опубликовано, в этих странах реклама не обслуживается
   или форма не показывается.
2. После публикации в Google Play: **Apps → Background Camera → App settings → Link to app store**,
   чтобы AdMob проверил приложение. До проверки показ рекламы может быть ограничен — это нормально.
3. **Payments** — укажите платёжные данные и налоговую информацию, иначе выплаты не пойдут.
4. Необязательно: `app-ads.txt` на сайте разработчика (нужен сайт, указанный в карточке Play).
5. **Тестовое устройство:** добавьте свой телефон в *Settings → Test devices*. Релизная сборка
   использует боевые блоки, и **нажимать на собственную рекламу нельзя** — это основание для блокировки
   аккаунта AdMob. Отладочные сборки (`assemblePlayDebug`) используют тестовые блоки Google и безопасны.

- [ ] Установить релизный `.aab` из Internal testing, пройти: запуск → согласие (если показано) → баннер.

## 11. F-Droid

Сборка F-Droid теперь называется `fossRelease`. В рецепте (`fdroiddata`) нужно указать
`gradle: [foss]` вместо `gradle: yes`. Сканер F-Droid ищет несвободные зависимости по тексту
Gradle-файлов, даже если они в `play`-ветке: если он ругнётся на строки `"playImplementation"(…)`,
добавьте в рецепт `prebuild`, который их удаляет, или `rm: [app/src/play]`. В `fastlane` добавлен
`changelogs/2.txt` для версии 2 (`versionCode = 2`, `versionName = "1.1"`).
